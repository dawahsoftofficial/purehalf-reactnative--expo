# Pure Half Mobile App — Audit Report (2026-05-27)

**Verification status**: items marked ✅ are independently verified by reading the source; items marked ⚠️ come from a subagent and should be re-read before fixing. Agent findings that turned out wrong have been removed.

**Static analysis baseline**: TypeScript `tsc --noEmit` is **clean**. ESLint reports **20 errors, 853 warnings**. Jest **fails to start**.

## CRITICAL (fix before next release)

### C1. ✅ Guardian OTP is a complete auth bypass — anyone can log in as user_id 5

**File**: `src/screens/guardian/GuardianOtpInput.tsx:50-90`
**Problem**: `onContinuePress()` runs as soon as 6 digits are entered. It does **not** call any API to verify the OTP. Instead it hardcodes `const currentUser = { id: 'guardian', role: 'guardian', user: { id: 5 } };` and writes that to global state + storage, then routes into Messages. Anyone who reaches this screen and types any 6 digits gets logged in as the guardian of user 5.
**Fix**: Call the real guardian OTP-verify endpoint (`POST /api/v1/app/guardian/authenticate` or equivalent in `admin/routes/api.php`), use the returned user object, and remove the hardcoded literal entirely.

### C2. ✅ Jest test suite cannot start — broken setup import

**File**: `jest-setup.ts:1`
**Problem**: `import '@testing-library/react-native/extend-expect';` — that subpath was removed in `@testing-library/react-native` v13+. Bundled matchers are now part of the main entry. Test suite fails on every run; CI signal is blind.
**Fix**: Replace with `import '@testing-library/react-native';` (or delete the line entirely — matchers extend automatically in v13+).

### C3. ✅ TypingIndicator violates React 19 ref purity — 19 lint errors

**File**: `src/screens/messages/components/TypingIndicator.tsx:12-94`
**Problem**: `Animated.Value` refs are created and `.interpolate()` is called during render. React 19 forbids reading refs during render (`react-hooks/refs`). Likely works today because `Animated` ref objects are special, but will break with React Compiler optimizations and is the only block of "errors" (not warnings) the linter reports.
**Fix**: Move the `useRef(new Animated.Value(0)).current` initialization out of render (e.g. into `useRef(() => new Animated.Value(0))` lazy init) and either pass the refs themselves into the JSX (Animated reads them at commit) or memoize the interpolated styles inside a `useMemo`.

### C4. ✅ Hardcoded "Alina Raza's" name shown to every guardian user

**File**: `src/screens/guardian/GuardianOtpInput.tsx:118`
**Problem**: Literal `{"Alina Raza's"}` rendered in the OTP description regardless of who the actual wali is. User-visible, ships in release.
**Fix**: Pass the wali's display name via route params (the same flow that opens this screen) and render that.

### C5. ✅ Axios middleware logs full request/response including Bearer token

**File**: `src/services/api/Middleware.tsx:39-47, 67-76, 84-95`
**Problem**: Every request and response is `console.log`-ed in full, including `headers` which contains `Authorization: Bearer <token>`. In React Native release builds, `console.log` is **not** stripped by default — output goes to logcat (Android) and OSLog (iOS), which other apps and crash reporters can read.
**Fix**: (a) Strip `Authorization` from the logged headers, (b) gate the entire log under `if (__DEV__)`, and (c) add `babel-plugin-transform-remove-console` to the prod babel config as defense-in-depth.

### C6. ✅ 400 responses log the user out (same branch as 401)

**File**: `src/services/api/Middleware.tsx:98`
**Problem**: `if (error?.response?.status === 401 || error?.response?.status === 400)` triggers `deleteAll()` + navigation reset to `AuthWelcome`. A 400 means "bad request" (validation error), not "unauthenticated" — any form-validation failure currently logs the user out and wipes their session.
**Fix**: Remove `|| === 400` from the condition. Handle 400s in the caller as validation errors.

### C7. ⚠️ Wali can be added without consent (no email-owner verification on the primary flow)

**File**: `src/screens/addWali/AddWali.tsx:135-196`
**Problem**: Submitting a guardian email triggers OTP only when the email _changes from an existing value_ (line 184). On first-time add (no existing guardian), the code path that sends OTP-to-email may be skipped depending on branch; needs a re-read of the AddWali state machine to confirm. If confirmed, a member can name any email as their wali without that person consenting.
**Fix**: Always require an OTP-to-wali-email round-trip before persisting the relationship.

### C8. ⚠️ Logout leaks Pusher / RevenueCat / FCM bindings

**File**: `src/navigation/CommonActions.tsx:35-56` (`handleLogout`)
**Problem**: Clears storage and `currentUser`, stops the Firestore conversations listener, but does **not**: (a) disconnect Pusher subscriptions, (b) call `Purchases.logOut()` to detach the RevenueCat user, (c) clear Zustand stores (`premium`, `settings`, `user-stats`, `conversation`). Next user signing in on the same device inherits cached counters and may see RevenueCat entitlement carryover.
**Fix**: Add `Purchases.logOut()`, `pusher.disconnect()`, and explicit `.reset()` (or equivalent setState to defaults) on every Zustand store inside `handleLogout`.

## MAJOR (fix soon — incorrect behavior on real user paths)

### M1. ✅ `ConversationsListener.getConversationsQuery(userId)` ignores its `userId` parameter

**File**: `src/services/firebase/ConversationsListener.tsx:37`
**Problem**: Param `userId` is unused (lint flagged it). Function returns `ref(database, conversationsPath)` unfiltered. If `conversationsPath` is global instead of user-scoped, the listener receives every user's conversations.
**Fix**: Either build the path as `conversations/{userId}` (if that matches Firestore structure) or apply `.orderByChild('userId').equalTo(userId)`. Read the Firebase RTDB rules to confirm structure before changing.

### M2. ⚠️ `pusher-service.tsx` useEffect missing `currentUser` dependency

**File**: `src/services/pusher/pusher-service.tsx:647`
**Problem**: Lint already flagged. Callback closes over `currentUser`; stale closure means counter updates apply to whoever was the user when the effect first ran.
**Fix**: Add `currentUser` to deps, or read `currentUser` from the store inside the callback (`useGlobalContext.getState()`-style escape) so the latest value is always used.

### M3. ⚠️ Pusher private-channel auth silently returns `{auth: ''}` on misconfig

**File**: `src/services/pusher/pusher-service.tsx:90-182`
**Problem**: When `authEndpoint` is missing or the auth request fails, the authorizer returns an empty auth string instead of throwing. Subscription fails silently — chat appears broken with no diagnostic.
**Fix**: Throw / reject in the authorizer error path; surface via Crashlytics.

### M4. ⚠️ FCM `onMessage` listener never unsubscribed; closes over stale handlers

**File**: `src/notifications/DisplayForegroundNotificaton.tsx:119-180`
**Problem**: `useEffect` with `[]` deps subscribes to `onMessage` and never returns a cleanup. After logout / user switch, callbacks still fire with the old user's navigation and context.
**Fix**: Capture the unsubscribe return value, return cleanup; consider listing real deps so the listener re-binds when the user changes.

### M5. ⚠️ Message-fetch and Pusher `MessageSent` race overwrite each other

**File**: `src/screens/messages/SingleChat.tsx:144-222`
**Problem**: `fetchMessages` and `handleNewMessage` both mutate `setMessages` against `messagesRef`. If a Pusher event lands while an HTTP fetch is in flight, the fetch response can clobber the realtime-added message.
**Fix**: Merge by message ID + `created_at` — fetched batch shouldn't replace existing entries with newer timestamps.

### M6. ⚠️ Pusher subscription overwrites previous unsubscribe ref on remount

**File**: `src/screens/messages/SingleChat.tsx:238-386`
**Problem**: `setupPusherListeners` reassigns `unsubscribeConversationRef.current` without calling the previous unsubscribe first → orphaned subscriptions.
**Fix**: `if (unsubscribeConversationRef.current) unsubscribeConversationRef.current();` before reassigning.

### M7. ⚠️ Typing indicator can stick on forever

**File**: `src/screens/messages/SingleChat.tsx:66-67, 486-490`
**Problem**: `setIsOtherUserTyping(false)` only fires when a new message arrives. If the other party stops typing without sending, indicator stays.
**Fix**: Auto-clear after ~3s with a debounced `setTimeout`, and on screen blur.

### M8. ⚠️ Search results pagination uses stale page number

**File**: `src/screens/searchProfiles/SearchResults.tsx:42-57`
**Problem**: `setsearchResultsPageNo(prev => prev + 1)` immediately followed by an API call that reads `searchResultsPageNo` → API gets the _old_ page.
**Fix**: Compute `nextPage = searchResultsPageNo + 1`, pass `nextPage` to the API call, then set state.

### M9. ⚠️ Welcome `onEndReached` retriggers on empty / short lists

**File**: `src/screens/welcome/UsersList.tsx:108-109`
**Problem**: No guard for `data.length === 0` or in-flight loader → cascade of identical pagination calls.
**Fix**: Early-return if `!data.length || loadMoreLoader`.

### M10. ⚠️ Swipe buttons can fire twice (no debounce / disabled state)

**File**: `src/screens/welcome/UsersList.tsx:108-109` + `src/components/SliderEntry.tsx:216-226`
**Problem**: Like/Pass buttons not disabled while the previous request is in flight → duplicate likes/passes.
**Fix**: Track per-card in-flight state; disable buttons while pending.

### M11. ⚠️ Premium check uses local state without re-verifying with server

**File**: `src/stores/premium-store.ts:25-29, 66-70` + various callers
**Problem**: `isPremium()` returns true if EITHER RevenueCat OR backend `membership_expiry` shows premium. Disagreement means the app trusts whichever says yes. Server should be source of truth for entitlements that depend on RevenueCat purchases.
**Fix**: Prefer RevenueCat when both sources are available; log Crashlytics warning on divergence; have backend webhook keep `membership_expiry` in sync.

### M12. ⚠️ Bank transfer screen lacks proof-of-payment upload

**File**: `src/screens/bankTransfer/BankTransfer.tsx`
**Problem**: Shows bank instructions and says "provide proof of payment" but has no file picker / upload / submit. User has no way to complete the flow inside the app.
**Fix**: Add proof-of-payment upload (existing `image-crop-picker` is already a dep) → POST to a new admin endpoint for manual review.

### M13. ⚠️ Account deletion doesn't clear local state / sign out Firebase

**File**: `src/services/api/Services.tsx:1011-1037`
**Problem**: Calls backend delete and resolves. Doesn't `deleteAll()`, doesn't `signOut(auth)`, doesn't stop listeners.
**Fix**: Run the same cleanup steps as `handleLogout` after a successful delete response.

### M14. ⚠️ Privacy settings toggle sends the entire user object on every flip

**File**: `src/screens/privacySettings/PrivacySettings.tsx:85-130`
**Problem**: Each toggle change ships first/last name, gender, DOB, lat/lng, plus all four privacy flags. One stale field can cause the whole update to fail or overwrite concurrent changes from another device.
**Fix**: Add a partial-update endpoint or send only the toggled key.

### M15. ⚠️ `BlockedList` unblock doesn't rerender (same array reference)

**File**: `src/screens/blockedList/BlockedList.tsx:122-125`
**Problem**: `_.remove(blockedList, …); setBlockedList(blockedList);` — React skips render because reference is unchanged. Unblocked user stays visible.
**Fix**: `setBlockedList([...blockedList])` or filter into a new array.

### M16. ⚠️ Notification permission requested on every app open

**File**: `App.tsx:42-52`
**Problem**: `useEffect` with `[]` deps; runs once per mount, but `App` remounts on cold start and on some hot reload paths. iOS no-op when already granted, but on Android 13+ it's wasted work and noise.
**Fix**: Check `getPermissionStatus()` first; only request if `notDetermined`.

### M17. ⚠️ Double-purchase risk in `ProFeaturesPromotion`

**File**: `src/screens/proFeaturesPromotion/ProFeaturesPromotion.tsx:220-275`
**Problem**: `onPackageSelection` doesn't lock against a second invocation while `Purchases.purchasePackage` is pending.
**Fix**: Set/check an `isPurchasing` ref before calling RevenueCat.

### M18. ⚠️ `restorePurchases` checks `activeSubscriptions.length !== 0` only

**File**: `src/screens/proFeaturesPromotion/ProFeaturesPromotion.tsx:104-106`
**Problem**: An expired subscription can still appear in `activeSubscriptions`. Length check incorrectly grants premium.
**Fix**: Also check `customerInfo.entitlements.active[ENTITLEMENT_ID]?.isActive === true`.

### M19. ⚠️ Hardcoded `'guardian'` magic string used to branch routing

**File**: `src/navigation/RootNavigation.tsx:85`
**Problem**: `if (res?.id === 'guardian')` is the only signal that the current user is a guardian. If the backend ever returns a numeric id (as it does for normal users), guardians silently route as members.
**Fix**: Backend should return a typed `role` field; check `res?.role === 'guardian'`.

### M20. ⚠️ Half-removed Boost feature in Welcome.tsx

**File**: `src/screens/welcome/Welcome.tsx:178, 193, 200, 273, 493, 612-614, 704, 741-766`
**Problem**: `loaded`, `userListPage`, `isBoostLoading`, `ensureActiveMembership`, `onBoostProfilePress`, `isBoosted` are all declared and unused; the boost FAB is commented out; a "TODO: Backend integration" sits near line 514.
**Decision needed**: keep Boost (re-wire it) or remove it (delete dead code).
